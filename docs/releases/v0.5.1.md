# EvoZeus v0.5.1

EvoZeus v0.5.1 保留 v0.5.0 的 Core Lesson runtime、CoEvolve v0.15.0 与 canonical Harness Skill v1.1.0 组合，并把正式发布资产升级为 fail-closed 事务。

> `v0.5.0` 最终已包含完整五项资产、摘要一致且可安装。它的原发布流程曾在资产完整确认前开放正式入口；`v0.5.1` 消除该窗口。

## 发布修复

Release workflow 从“先发布、再上传”升级为五段 fail-closed 事务：

1. 在创建正式入口前确认仓库已启用 immutable Releases。
2. 创建或复用 draft Release，验证 Tag，并同步正式标题与 Release Notes。
3. 上传 preflight、两份 checksum、Core archive 和 Stable product manifest 共五个资产。
4. 核对精确资产集合，并将每个本地 SHA-256 与 GitHub asset digest 逐项比较。
5. 全部通过后发布，随后断言 `isDraft=false` 且 `isImmutable=true`。

任何大文件上传失败都会把 Release 保留在 draft，正式入口不会出现缺失资产的版本。

## 版本组合

| 层级 | 版本 | 开发维度与职责 |

| EvoZeus Core | `v0.5.1` | 代码：产品安装、通道、普通聊天事件、目标选择与 Lesson runtime |

目标 Skillware 的业务版本继续独立演进。

## 产品升级

- Stable `v0.4.1`：在 SessionStart 或 EvoZeus/CoEvolve 受管入口自动更新到 `v0.5.1`；也可在明确批准后主动对齐。
- Stable `v0.4.0` 及更早版本：先显式执行一次对齐，进入支持自动同渠道更新的基线。
- 新安装：从官网 Install Skill 进入 Stable preflight、批准安装、Host 注册和 Doctor。

```text
evozeus align --channel stable --host auto --approve-write --json
```

完成后重开 Codex 或 Claude 会话，使新生命周期生效。

## 历史 Harness 迁移

产品对齐不会改写目标 Repo。EvoZeus/Agent 从 active product manifest 解析受信 CoEvolve `v0.15.0` component root，再为单个目标执行 `harness migrate-layout --dry-run`：

- canonical Harness `v1.0` 完整匹配官方 closure：automatic migration。
- legacy `v0.14` 三段式完整匹配已审查 preimage：supervised migration。
- 证据不完整、布局歧义或业务内容不匹配：`manual_migration_required`，零写入。

heading、frontmatter、regex 与旧路径仅发现候选。写入仍要求 release-bound profile、exact preimage、干净工作区、exact plan digest 与 receipt-bound rollback。

## 验证范围

- 完整 Node、Python、Plugin、Channel、Doctor、Harness boundary 与 GitHub governance suites。
- 单一 `uat/current` 的 Core/CoEvolve exact Commit、required paths、Runtime 与 Session Signal 兼容性。
- correction、neutral、ambiguous 原生 Hook 事件、唯一目标选择、静默继续、零持久化与第三方 Hook 保留。
- 正式 Core archive checksum、Stable manifest、Tag Commit 与 archive tree identity。
