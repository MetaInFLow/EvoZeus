# EvoZeus v0.5.0

EvoZeus v0.5.0 将普通聊天中的 Lesson 识别纳入 Core 受信运行时，并把 CoEvolve v0.15.0 的 canonical Harness Skill 与历史迁移闭包纳入同一套 Stable 完整性校验。

## 版本组合

| 层级 | 版本 | 职责 |
| --- | --- | --- |
| EvoZeus Core | `v0.5.0` | 产品安装、通道切换、普通聊天事件读取、目标选择与 Lesson runtime |
| CoEvolve | `v0.15.0` | Harness 注册、升级计划、迁移执行、校验与 rollback |
| Consumer contract bundle | `v1.2.0` | 约束 Core runtime、CoEvolve lifecycle 与兼容区间 |
| canonical Harness Skill | `v1.1.0` | 目标 Repo 内的运行检查、Feedback、Issue-to-PR、维护、UAT、Release 与 rollback 规则 |

目标 Skillware 的业务版本继续独立演进，不与上述四层版本绑定。

## 主要变化

- Core 新增 `evozeus.user-prompt.lesson-runtime.v1`。受信 dispatcher 在普通聊天中读取事件、选择唯一注册目标，并调用内置 Session Signal；输出保持私密、有限、零持久化，异常时静默继续聊天。
- Stable 固定 CoEvolve `v0.15.0` 的 immutable Release 资产、Commit 与 SHA-256，同时校验 contract `v1.2.0`、canonical Harness Skill `v1.1.0`、迁移 profiles、closure 和 official-upgrade verifier 均完整存在。
- 目标业务入口只保留紧凑 activation block，Harness 治理规则集中在 `.evozeus-wrapper/skills/using-evozeus-harness/SKILL.md`。
- CoEvolve 负责生命周期注册与迁移；Core 负责普通聊天 Lesson runtime。两者通过明确合同协作，安装时会核对 active product manifest、dispatcher bytes、runtime API 与 HOME 边界。

## 产品升级

升级路径按现有产品状态分流：

- 已安装 Stable `v0.4.1`：在 SessionStart 或 EvoZeus/CoEvolve 受管入口自动发现并事务更新，无需重复初始化；也可在明确批准后主动执行下方对齐命令。
- 已安装 Stable `v0.4.0` 及更早版本：先执行一次受信通道对齐，进入支持自动同渠道更新的 `v0.4.1+` 基线。
- 新安装：从官网 Install Skill 进入 Stable preflight、批准安装、Host 注册和 Doctor 流程。

显式对齐命令：

```text
evozeus align --channel stable --host auto --approve-write --json
```

对齐会把 Core、CoEvolve、Runtime、Session Signal 和 Host plugin 作为一个已验证事务更新。激活指针仅在完整性检查、Host 注册和 Doctor 通过后切换；失败时保留或恢复上一个已验证版本。

完成后重开 Codex 或 Claude 会话，使新的 SessionStart / UserPromptSubmit 生命周期生效。

## 历史 Harness 迁移

产品升级不会直接改写目标 Repo。EvoZeus/Agent 先从 active product manifest 解析并验证当前 CoEvolve `v0.15.0` component root，再从该根目录为每个目标生成只读迁移计划：

```text
python3 scripts/evozeus_wrapper.py harness migrate-layout \
  --target /absolute/path/to/repo \
  --latest-version v0.15.0 \
  --dry-run \
  --json
```

计划按证据分流：

- canonical Harness `v1.0` 完整匹配官方 closure：进入 `automatic_migration_available`。
- legacy CoEvolve `v0.14` 三段式布局完整匹配已审查 preimage：进入 `supervised_migration_available`。
- 证据不完整、布局有歧义或受保护业务内容不匹配：返回 `manual_migration_required`，保持零写入。

历史 heading、frontmatter、regex 和旧路径只用于发现候选。写入授权同时要求 release-bound migration profile、完整 exact preimage、干净工作区和本次计划的 exact digest。审查 write / delete / move、受保护内容与 rollback 信息后，提交同一 digest：

```text
python3 scripts/evozeus_wrapper.py harness migrate-layout \
  --target /absolute/path/to/repo \
  --latest-version v0.15.0 \
  --approve-plan 'sha256:<operation_sha256-or-plan_sha256>' \
  --json
```

每次 apply 都会在目标 Repo 外生成 receipt-bound 完整 snapshot；中途失败先自动恢复并验证 preimage，必要时可通过 `rollback-migration` 使用受信 snapshot 人工恢复。

## 验证范围

- Node plugin、Host、Installer、Doctor、Channel、Release Notes、Harness boundary 与 GitHub governance suites。
- Python Runtime 与 Session Signal suites。
- CoEvolve v0.15.0 Release 资产的 GitHub digest、checksum 文件与本地流式 SHA-256 三方一致。
- fresh-chat UAT 覆盖 correction、neutral、ambiguous 三类输入，验证唯一目标 Lesson guidance、普通消息静默继续、歧义零选择、零持久化与第三方 Hook 保留。
